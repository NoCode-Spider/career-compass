# 07-技能盘点与差距分析

> 适用场景：不知道自己有什么能力、不知道目标岗位差距在哪、不知道学什么。
> 目标读者：职业迷茫者、准备转行/跳槽的人。

---

## 一、技能盘点

### 1.1 KSAO 四维度盘点

按 KSAO 框架逐一盘点，每个维度都要有**具体事件支撑**，不能只说"我觉得我还行"。

#### Knowledge 知识
| 知识领域 | 掌握程度 | 怎么获得的 | 可以迁移到 |
|---------|---------|-----------|-----------|
| 例：互联网运营知识 | 熟练 | 3 年工作经验 | 产品/营销/内容 |
| 例：会计学基础 | 入门 | 大学专业 | 财务/数据分析 |
| | | | |
| | | | |

#### Skills 技能
| 技能 | 熟练度 | 展示案例 | 可迁移性 |
|------|--------|---------|---------|
| 例：Excel 数据分析 | 熟练 | 每月做运营数据报表，用透视表+函数 | 高（任何岗位都用得到） |
| 例：用户访谈 | 掌握 | 做过 20+ 用户深度访谈 | 中高（产品/用研/运营） |
| | | | |
| | | | |

#### Abilities 能力
| 能力 | 表现 | 具体事件 |
|------|------|---------|
| 逻辑分析 | 强/中/弱 | 例：通过数据分析发现用户流失原因，提出优化方案 |
| 沟通表达 | 强/中/弱 | 例：在跨部门项目中协调 5 个团队推动落地 |
| 学习能力 | 强/中/弱 | 例：入职 1 个月独立负责核心模块 |
| 创造力 | 强/中/弱 | 例：提出 XX 创意方案，被公司采纳 |
| 执行力 | 强/中/弱 | 例：项目延期时加班加点按时交付 |

#### Other 其他特质
| 特质 | 表现 | 具体事件 |
|------|------|---------|
| 责任心 | 强/中/弱 | 例：主动承担出错的责任并修复 |
| 细节导向 | 强/中/弱 | 例：发现了别人没注意到的数据错误 |
| 抗压能力 | 强/中/弱 | 例：双 11 期间连续加班 1 个月保持产出 |
| 主动性 | 强/中/弱 | 例：主动优化了工作流程，效率提升 30% |

### 1.2 盘点注意事项

- **用具体事件说话**："我做过 XX 项目，取得了 XX 成果" > "我沟通能力不错"
- **不要过度谦虚**：很多人低估自己的技能——你觉得"基础"的技能，别人可能觉得"厉害"
- **不要夸大**：面试时被问倒更尴尬
- **找朋友帮忙看**：别人眼中的你和你自己眼中的你可能不一样

## 二、目标岗位差距分析

### 2.1 收集目标岗位要求

从 5-10 个目标岗位 JD 中提取高频要求：

| 要求类别 | 高频关键词 | 出现次数 | 我的匹配度 |
|---------|-----------|---------|-----------|
| 硬技能 | 例：SQL、Python | 8/10 | 入门 |
| 经验要求 | 例：3 年以上相关经验 | 10/10 | 无直接经验 |
| 软技能 | 例：沟通协调 | 7/10 | 强（可迁移） |
| 学历要求 | 例：本科以上 | 10/10 | 匹配 |

### 2.2 差距优先级矩阵

```
         重要性高
           │
    第一象限 │  第二象限
    重要+紧急 │ 重要+不紧急
    先学这个  │  计划学习
   ─────────┼─────────
    第三象限 │  第四象限
    不重要+紧急│ 不重要+不紧急
    可以委托 │  暂时不学
    或快速补  │
           │
         重要性低
```

### 2.3 差距分类处理

| 差距类型 | 怎么补 | 时间 |
|---------|--------|------|
| **硬技能（必须会）** | 系统课程 + 刻意练习 + 项目实战 | 1-6 个月 |
| **行业知识** | 看书 + 行业报告 + 信息访谈 | 2-4 周 |
| **作品集/案例** | 做 2-3 个练手项目 | 1-2 个月 |
| **软技能** | 面试中用过往案例展示 | 已有，不需专门学 |
| **证书/学历** | 评估是否真的必要，很多是"优先"不是"必须" | 6 个月以上 |

## 三、学习路径设计

### 3.1 学习计划模板

```
目标岗位：____________
预计准备时间：____ 个月

## 第 1 阶段（第 1-4 周）：基础入门
- [ ] 学完《XX 入门课程》
- [ ] 读完《XX 书》
- [ ] 完成 3 篇行业深度阅读
产出：知识框架笔记

## 第 2 阶段（第 5-8 周）：技能练习
- [ ] 学完《XX 进阶课程》
- [ ] 完成 5 个练习任务
- [ ] 做 1 个完整练手项目
产出：练手项目 1

## 第 3 阶段（第 9-12 周）：项目实战
- [ ] 完成第 2 个练手项目
- [ ] 找 2-3 位业内人士做模拟面试
- [ ] 优化简历和作品集
产出：作品集 + 改好的简历

## 第 4 阶段（第 13 周起）：求职投递
- [ ] 开始投递
- [ ] 边面试边补短板
```

### 3.2 70-20-10 原则应用

不要把 100% 的时间花在"上课"上（正式学习只占 10%）。按 70-20-10 分配：

| 比例 | 方式 | 做什么 |
|------|------|--------|
| 70% | 实践 | 做项目、解决真实问题、练手 |
| 20% | 社交学习 | 找从业者聊、加社群、找导师 |
| 10% | 正式学习 | 上课、读书、看教程 |

**常见错误：** 花了 3 个月上课（10% 的部分），但一个项目都没做（70% 的部分）。结果是"学了很多但不会用"。

## 四、技能提升策略

### 4.1 硬技能提升

1. **找一个好的入门课程**：不要找"最全"的，找"最适合初学者"的
2. **学完一个模块立即练习**：不要全部学完才练
3. **做项目式学习**：带着项目目标去学，比纯听课有效 10 倍
4. **找反馈**：作品发出去让人看，或找前辈点评
5. **费曼学习法**：学完后尝试教给别人——讲不清楚的地方就是没懂的

### 4.2 软技能提升

软技能很难通过"上课"提升，要在实践中刻意练习：

| 软技能 | 练习方法 |
|--------|---------|
| 沟通表达 | 每次开会刻意发言 1 次；写周报时练习结构化表达 |
| 逻辑思维 | 做决策时用结构化框架（如 MECE）；写作时先列大纲 |
| 时间管理 | 用番茄工作法；每周做计划和复盘 |
| 领导力 | 主动牵头一个小项目；带新人 |

### 4.3 避免学习陷阱

| 陷阱 | 表现 | 怎么破 |
|------|------|--------|
| **收藏即学习** | 收藏了一堆课程/文章但没看 | 收藏后 48 小时内必须看 |
| **只输入不输出** | 学了很多但没做过项目 | 每学一个知识点就找一个应用场景 |
| **完美主义** | 要"学完"才敢投简历 | 学到 60% 就可以开始投，边面边补 |
| **贪多求全** | 什么都想学 | 先学最重要的 20%（80/20 法则） |
| **不停换方向** | 今天学这个明天学那个 | 选定一个方向至少坚持 3 个月 |

## 五、定期复盘

### 5.1 月度技能复盘表

| 技能 | 上月水平 | 本月水平 | 提升了多少 | 做了什么 | 下月计划 |
|------|---------|---------|-----------|---------|---------|
| 例：SQL | 入门 | 掌握 | 能写复杂查询 | 学了课程+做了 10 道练习题 | 学优化和索引 |
| | | | | | |
| | | | | | |

### 5.2 季度差距再评估

每 3 个月重新做一次差距分析：
- 哪些差距补上了？
- 哪些还没补上？为什么？
- 有没有发现新的差距？
- 学习计划需要调整吗？

- [ ] 按 KSAO 四维度完成了自我盘点

- [ ] 收集了 5-10 个目标岗位 JD
- [ ] 提取了高频要求
- [ ] 做了差距优先级排序
- [ ] 设计了 70-20-10 的学习路径
- [ ] 有明确的阶段目标和产出物
- [ ] 设置了定期复盘机制

---

> **停止条件：** 如果你已经"学"了 6 个月以上，但还是觉得"没准备好"不敢投简历，问题可能不是能力不够，而是"完美主义"或"害怕失败"。学到 60-70% 就可以开始投递了——面试本身也是最好的学习方式，能让你知道市场真正需要什么。
